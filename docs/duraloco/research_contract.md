# DuraLoCo Research Contract

Status: frozen for Protocol v2 reference work (P00). This contract describes
claims to be tested; it does not claim that the legacy runtime already meets
them.

## Terms

- **Proposal:** one immutable fragment contribution produced by a learner from
  a named causal base and a non-overlapping local contribution interval.
- **Commit:** a deterministic optimizer transition that becomes authoritative
  only when the single global head is conditionally replaced.
- **Frontier:** the complete versioned view of every parameter fragment and its
  paired outer-optimizer state at one committed sequence.
- **Head:** the sole mutable authority pointer to the newest committed
  frontier. Immutable prepared objects are not committed merely because they
  exist.
- **Logical inclusion:** a proposal's contribution to the committed optimizer
  trajectory. At-least-once storage observations may occur, but a proposal ID
  may appear in at most one committed transition.
- **Global exact recovery:** reconstruction of parameters, per-fragment outer
  state, scheduler state, and proposal-consumption state for exactly the
  committed prefix named by head.
- **Warm learner restart:** creation of a new learner session from the latest
  global frontier while reinitializing private optimizer, RNG, scheduler, and
  data-cursor state. It is not trajectory-exact.
- **Exact learner restart:** restoration from a consistent learner capsule plus
  a committed suffix, including private optimizer, RNG, scheduler/scaler, data
  cursor, and pending-interval state.

## Commit and authority model

The target authority is an event-sourced committed transition log. Large
proposal, parameter, and optimizer objects are immutable. A small conditional
head replacement is the only transition linearization point. A frontier must
refer to both the new parameter fragment and the outer state generated by the
same commit. Directory or object listing is discovery only.

The current prototype is a baseline with distributed authority: filesystem
payloads and JSON markers, `control/latest.json`, and syncer-local SQLite. No
P00 artifact describes that baseline as exactly-once, prefix-recoverable, or
failover-safe.

## Recovery guarantees

1. Global exact recovery is a Protocol v2 safety requirement and must equal a
   fold of the head-reachable committed prefix.
2. Warm learner restart is a supported but explicitly non-exact recovery mode;
   uncommitted local work and private optimizer/RNG/data state may be lost.
3. Exact learner restart is a later lifecycle feature and requires a complete,
   validated learner capsule. Fragment proposals alone are insufficient.

## Research claims and non-claims

The work tests whether durable optimizer transitions can replace or reduce the
separate full-global-checkpoint path in low-communication asynchronous
training, while preserving a measurable numeric contract and improving
failure goodput in some operating region.

It does not claim to replace NCCL/RDMA for high-frequency synchronization,
provide exactly-once delivery, tolerate Byzantine learners, survive loss of
storage-confirmed durable objects, make every learner proposal a full
checkpoint, guarantee bitwise full-training replay, or outperform every
backend, model scale, local interval, and failure rate.

## Evidence discipline

Planned targets and observed measurements remain separate. Every result must
bind the code commit, dirty-tree status, config digest, environment, backend,
seed, commands, and raw artifacts. Synthetic and in-memory evidence is not
reported as Lustre, GPU, or model-quality evidence.
